Tools: giving AI hands

A model can only produce text. Tools let that text turn into actions: looking things up, calculating, updating systems.

⏱ 30 sec

🎤 Say A model can only produce text. Tools turn that text into actions: looking things up, calculating, updating systems.

  • Also called function calling or tool use. Same thing.
The key insight

The model doesn’t run tools. It asks for them.

Like a surgeon saying “scalpel”: the model writes a structured request, your software carries it out, and the result goes back to the model.

⏱ 2 min

🎤 Say The key point: the model does not run tools. It asks for them, and your software decides whether to carry out the request.

  • Crucial for safety: your software decides whether to actually run the request. That’s where permissions and approvals live (Topic 18).

Tool design

The model only knows a tool by its description

Request: “Find Dana Lee’s email address.” Compare vague and clear tool descriptions.

⏱ 2 min

🎤 Say The model knows a tool only by its description. Vague descriptions get the wrong tool or no tool at all.

  • Tool descriptions are prompts too. Everything from Topic 7 applies: be specific, say when to use it and when not to.

Risk

Not all tools are equally risky

Classify each tool by what could go wrong. This decides how much approval it needs.

⏱ 2 min

🎤 Say Not all tools carry the same risk. Reading is safe, reversible changes need logging, and irreversible actions need a human to approve.

  • Simple policy many teams use: read-only tools run freely, reversible writes are logged, and irreversible actions need a human to click Approve.
