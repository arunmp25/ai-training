Agent design patterns

Most good “agents” are not one big agent. They are a few model calls arranged in a proven shape: a chain, a router, parallel checks, an orchestrator, a reviewer, or a fully autonomous loop. Each pattern below is animated with a claims example.

⏱ 30 sec

🎤 Say Now let us look at the shapes that AI systems come in. Most production systems use one or two simple patterns, not a fully autonomous agent.

  • The pattern names follow Anthropic’s widely cited guide “Building effective agents”, plus the common multi-agent and human-in-the-loop patterns.
The map

From workflow to agent: start with the simplest that works

Left to right: less control by your code, more by the model. More autonomy means more cost, more latency and more ways to go wrong. Click each step.

Workflows (patterns 1–5): your code decides the path. Agents (patterns 6–7): the model decides. Human in the loop (8) can wrap any of them.
⏱ 2 min

🎤 Say Here is the map. On the left, workflows: your code decides the path, and the model fills in each step. On the right, agents: the model decides the path. Move right only when you need to.

  • Every step to the right adds capability and adds cost, latency and risk.
  • The building block of all of them is the augmented LLM: one model call with tools, retrieval and memory.
Pattern 1 of 8 · animated

Prompt chaining: a fixed sequence of steps

Each model call does one job and passes its output to the next. Code checks in between.

⏱ 3 min

🎤 Say Prompt chaining splits a task into fixed steps, each a small focused model call, with ordinary code checking the output in between. It is the simplest pattern and often the right one.

  • Run “Complete claim”, then “Missing details” to show the gate earning its keep.
  • This is a workflow, not an agent: your code decides the order.
  • In LangGraph each step is a node and the gate is a conditional edge.
Pattern 2 of 8 · animated

Routing: classify first, then send to a specialist

A quick classification decides which prompt, model or team handles the request.

⏱ 2 min

🎤 Say Routing classifies the input first and sends it to the right specialist: a different prompt, a different model, different tools, or a person. A small, fast model is usually enough for the router.

  • Using a cheap model for the router and a stronger one only where needed saves real money at volume.
  • Routing also limits blast radius: the quotes branch cannot touch claims data.
Pattern 3 of 8 · animated

Parallelisation: several calls at once, then combine

Independent checks run side by side (sectioning), or the same question is asked several times (voting).

⏱ 3 min

🎤 Say Parallelisation runs several model calls at the same time. Sectioning splits a job into independent parts. Voting asks the same question several times to get a more reliable answer.

  • Sectioning is about speed and focus; voting is about confidence.
  • In LangGraph, the Send API fans out work to parallel nodes (shown later in this topic).
Pattern 4 of 8 · animated

Orchestrator–workers: a lead model plans and delegates

Like parallelisation, but the subtasks are not fixed in advance. The orchestrator decides them for each request.

⏱ 3 min

🎤 Say Orchestrator–workers is like parallelisation, except the subtasks are decided at run time by a lead model. A complex claim gets three workers; a simple one gets one.

  • Compare with the multi-agent architecture in Topic 15: that was this pattern with full agents as workers.
  • Claude Code’s subagents and research agents work this way.
Pattern 5 of 8 · animated

Evaluator–optimiser: write, review, improve

One model writes; another checks against clear criteria and sends feedback until it passes.

⏱ 2 min

🎤 Say Evaluator–optimiser pairs a writer with a reviewer. The reviewer checks the draft against written criteria and sends feedback until it passes, or until a round limit.

  • The criteria are the secret. Vague criteria (“make it better”) give endless loops.
  • This is also called reflection. It is how many coding agents fix their own failing tests.
Pattern 6 of 8 · animated

Autonomous agents: ReAct or plan-and-execute

Two common ways to structure a fully autonomous agent: decide one step at a time, or write a plan first.

⏱ 3 min

🎤 Say When the steps really cannot be known in advance, you need an autonomous agent. ReAct decides one step at a time. Plan-and-execute writes a plan first, executes it, and re-plans when something changes.

  • Claude Code does a mix: it often writes a to-do list (plan) and then works through it with ReAct-style steps.
  • A visible plan is also a good place for a human check before anything happens.
Pattern 7 of 8 · animated

Multi-agent: a supervisor, or agents handing off

Several specialised agents, each with its own prompt, tools and context. Who decides who works next?

⏱ 3 min

🎤 Say With several specialised agents, someone has to decide who works next. In the supervisor pattern a central agent decides every time. In the handoff pattern, agents pass the conversation directly to each other.

  • Each agent has a narrow prompt and only its own tools, which helps accuracy and security.
  • Multi-agent systems cost more and are harder to debug. Use them when one agent’s context or tool list gets too big.
Pattern 8 of 8 · animated

Human in the loop: pause for approval on risky steps

The agent works on its own until it reaches an action that matters. Then it stops and waits for a person.

⏱ 2 min

🎤 Say Human in the loop lets the agent work alone on safe steps and stops it before risky ones. The run pauses, the state is saved, a person approves or rejects, and the run resumes.

  • This is why LangGraph’s saved state matters: the pause can last minutes or days.
  • Harnesses do the same with permission prompts (Topic 17).

Takeaways

What to remember

🪜 Start simple

Use a single call, then a workflow. Reach for an agent only when the steps depend on what it finds.

🧭 Eight shapes

Chaining, routing, parallel, orchestrator–workers, evaluator–optimiser, ReAct or plan-and-execute, multi-agent, human in the loop.

✋ People for risky steps

Pause before actions that move money, send things out or cannot be undone.

Remember agent harnesses (Topic 16): Claude Code and GitHub Copilot package these patterns, with tools, memory and permissions, ready to use.
