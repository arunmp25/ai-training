The “lethal trifecta”

A useful rule of thumb (coined by Simon Willison): an agent becomes dangerous when it has all three of these. Switch them on.

⏱ 2 min

🎤 Say An agent becomes dangerous when it has all three: private data, untrusted content and a way to send data out. Remove at least one.

  • The email agent on the last slide had all three: private data (invoices), untrusted content (incoming email), and a way out (send email).
  • Design fix: remove at least one leg, or put a human approval on the “way out”.

Quality

Evals: “it worked when I tried it” isn’t evidence

An eval is a set of test cases you run every time you change the prompt, model or tools. Run the 20 support-bot test cases for each prompt version, several times.

Pass rate
—
💡 Notice the pass rate varies between runs because outputs aren’t deterministic. Run evals several times, and compare versions on the same test set.
⏱ 3 min

🎤 Say It worked when I tried it is not evidence. Evals are test cases you run every time you change the prompt, model or tools.

  • v1 looked fine in a demo, but it’s about 70% on real cases. v2 is more consistent.
  • Evals can be checked by code (did it return valid JSON?), by people, or by another model acting as a judge.

Observability: the black-box recorder

A trace records every step an agent took: what it saw, which tools it called, how long each step took and what it cost. Expand the steps.

  • Also essential for audits and for spotting cost blow-ups.
