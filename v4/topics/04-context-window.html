The context window: the AI’s desk

Everything the model uses must be on its desk at the moment it answers. How big is the desk, what’s on it, and what falls off?

⏱ 30 sec

🎤 Say Think of the context window as the AI’s desk. It can only use what is on the desk when it answers. Today: how big the desk is, what is on it, and what falls off.

  • Analogy for the whole topic: a desk. The model can only use papers on the desk. It can’t open drawers by itself (unless it has tools).
Example

⏱ 3 min

🎤 Say When the desk is full, something has to go. Dropping the oldest messages loses facts. Summarising keeps the gist, and that is called compaction.

  • Run it with “Drop oldest” first: the AI forgets Sam’s name, because that message fell off the desk.
  • Then with “Summarise”: the old messages are compressed into a note (called compaction), so the key facts survive.
  • Agent harnesses do compaction automatically on long tasks (Topic 17).
Memory

“Memory” features work by saving notes and putting them back on the desk in the next chat. Flip the switch.

⏱ 2 min

🎤 Say The model remembers nothing between chats. Memory features save notes and put them back on the desk next time. The app remembers, not the model.

  • Key point: the model never learns from your chat. The app around it (the harness) saves a note and adds it to the context next time.
  • Same idea as instruction files like CLAUDE.md (Topic 18).

Takeaways

What to remember

🗂️ The desk

The context window is everything the model can see right now: instructions, history, documents, tool results, your message.

🫥 No real memory

Memory is the app putting notes back on the desk. Overflow means dropping or summarising.

💸 Every token counts

Bigger context = more cost, slower answers and more noise. Put on the desk only what’s needed.
