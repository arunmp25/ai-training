Agent harnesses: the car around the engine

The model decides. The harness does everything else: runs the loop, executes tools, manages context and memory, enforces permissions. It’s where agents become reliable. Which is better, a Ferrari or a tractor? Depends whether you’re ploughing a field.

    Worked example

    One Guidewire bug, three kinds of harness

    After an age-band change, the GUnit test YoungDriverSurchargeTest fails. The model could be the same in all three; the harness changes how you work with it.

    ⌨️ Terminal agent

    e.g. Claude Code, Codex CLI
    You start it
    > YoungDriverSurchargeTest fails since the age-band change. Fix it.
    It works
    1. Reads AGENTS.md, runs ./gwb test to see the failure
    2. Finds the band moved from <21 to <=21 in hs.rating
    3. Fixes it, re-runs the tests, asks before each edit
    You get back
    A fixed file on your machine and a summary. You review the diff and commit.
    Good when: you want to watch and steer, step by step.

    🧑‍💻 IDE agent

    e.g. GitHub Copilot or JetBrains AI in Guidewire Studio (IntelliJ)
    You start it
    Select the failing test → “Fix this test”
    It works
    1. Uses the open file and the test output in the editor
    2. Suggests a change inline, with the reason
    3. You accept, tweak or reject it in the editor
    You get back
    An inline edit in the file you’re already working on.
    Good when: it’s a small change and you’re already in Studio.

    ☁️ Cloud agent

    e.g. Copilot coding agent, Codex cloud, Claude Code on the web
    You start it
    Assign Jira PC-1490 or a GitHub issue to the agent
    It works
    1. Clones the repo into a sandbox, reads AGENTS.md
    2. Fixes the band, runs the build and GUnit tests there
    3. Opens a pull request with the test results
    You get back
    A pull request to review, maybe an hour later. Your laptop was never involved.
    Good when: the task is well defined and you have other work to do.
    ⏱ 3 min

    🎤 Say Here is one real bug handled three ways. The engine underneath can be the same model; what changes is where it runs, how much it does on its own, and what you get back: an edit you watch, an inline suggestion, or a pull request.

    • All three read the same AGENTS.md, which is why Topic 17 recommends one shared instruction file.
    • The cloud agent needs the build to run in its sandbox. For Guidewire that means the environment setup must include the JDK and build dependencies.
    • Product names are a snapshot and change often; check them before you present.
