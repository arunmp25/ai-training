⏱ 3 min
🎤 Say Subagents keep the main desk clean. They do the research in their own context and return only a summary.
  • Subagents = the “isolate” move from Topic 8.
  • Also useful for specialists: a security reviewer with read-only tools and a strict checklist, or a test writer.
  • Trade-off: more total tokens, and they can’t see each other’s work.






  
Hooks & permissions

  
Guaranteed rules: hooks and permissions

  
Instructions are requests; hooks and permissions are enforced. The agent tries to run each command below. Click one and see what happens.

  

  

    
Pick a command above.

    

      
The rules in this project

      
// .claude/settings.json
"permissions": {
  "allow": ["Bash(pnpm test:*)", "Bash(git status)"],
  "deny":  ["Read(./.env)"]
},
"hooks": {
  "PreToolUse":  [ block dangerous commands ],
  "PostToolUse": [ run formatter after edits ]
}

    

  

  
⏱ 3 min
🎤 Say Instructions are requests. Hooks and permissions are enforced. Click each command and see what the harness does.
  • Order: permission rules decide allow / ask / deny; a PreToolUse hook can still block; after the tool runs, PostToolUse hooks fire.
  • Other hook events include session start, prompt submitted, agent stopping, and before compaction.

Takeaways

  
What to remember

  

    
📌 Always vs on demand
Instruction files are always loaded; skills load when relevant; subagents work in their own context.

    
🪝 Requests vs rules
If it must happen, use a hook or a permission, not a sentence in a prompt.

    
📦 Share it
It’s all files: commit them, or bundle them as a plugin so the whole team gets the same agent.
