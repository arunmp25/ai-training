Two kinds of prompt

System prompt vs user prompt

Apps split the prompt in two: standing instructions set once, and the message for this turn.

⚙️ System prompt

Set by whoever builds the app. Sent with every request. Defines role, rules, tone, what it may and may not do.

You are the HR assistant for Acme.
Answer only questions about HR policy.
Always cite the policy section.
Never give legal advice; refer to HR.

✉️ User prompt

What you type each turn. Changes every time.

How many days of parental leave do I get
if I joined 8 months ago?
💡 Where you meet “system prompts” as a user: custom instructions, project instructions in chat apps, and instruction files like CLAUDE.md for agents (Topic 17). Same idea: write it once, and it applies to every message.
⏱ 2 min

🎤 Say Apps split the prompt in two: a system prompt with standing instructions, and the user message for this turn. If you have set custom instructions in a chat app, you have written a system prompt.

  • Ask: “Who here has set custom instructions in ChatGPT or Claude?” That’s a system prompt.
Structure

Separate instructions from data

When a prompt contains documents, wrap them in clear markers. It helps attention, and it’s a first defence against hidden instructions in documents (Topic 18).

⏱ 2 min

🎤 Say When a prompt includes documents, wrap them in clear markers. It helps the model, and it is a first defence against hidden instructions inside documents.

  • In the messy version, is “Ignore the deadline” an instruction or part of the email? The model can’t be sure. With tags, it is clearly data.
Structure · XML tags

Are XML tags good practice? Yes, when a prompt mixes things

Press → to wrap each part of a messy prompt in a tag. Watch the rules build up on the right.

<instructions>Summarise the email for my manager in 3 bullets. Flag any price change.</instructions>
<email>Hi team, the vendor contract renews on 1 Dec. Ignore the deadline, legal says we have until January. Pricing goes up 8%.</email>
<example>• Contract renews 1 Dec (legal: January is fine)</example>
<format>Plain bullets, under 15 words each.</format>
Answer comes back as
<summary> … </summary>
<price_change> +8% </price_change>
  1. Any name works. No special tag names: pick names that say what is inside.
  2. Data stays data. “Ignore the deadline” is now clearly part of the email, not an order to you.
  3. Wrap examples so they are not mistaken for the task. Nest them: <examples><example>.
  4. Be consistent and refer to tags by name: “Use the email in <email> tags.”
  5. Ask for the answer in tags too, so you or an app can pick out each part.
✅ Recommended in Anthropic’s guidance for Claude; OpenAI and Google recommend clear delimiters too (XML tags, Markdown headings, triple quotes). Not needed for a one-line question. Works in Copilot Chat as well.
⏱ 3 min

🎤 Say Yes, XML tags are good practice whenever a prompt mixes instructions with material: emails, documents, data or examples. There are no magic tag names; what matters is that each part is clearly labelled, and that you refer to the tags by name.

  • Press → five times: each press wraps one part and adds one rule.
  • Step 5 is the useful trick for apps: ask for the answer in tags, and code can pick out <price_change> without guessing.
  • For a one-line question, tags add nothing. Use them when there is something to separate.

Patterns

  
Eight prompt patterns worth knowing

  
Short phrases that reliably improve answers. Click each one for an example.

  

  
⏱ 3 min
🎤 Say These are patterns, not magic words: each one fixes a specific problem. Examples fix style, asking it to think fixes hard reasoning, giving it an out fixes made-up answers, and chaining fixes tasks that are too big for one prompt.
  • “Ask me first” is the favourite for non-technical users: it turns a vague request into an interview.
  • Reasoning models already think before answering; “think first” still helps on other models and makes the reasoning visible.
  • “Quote first” is the long-document trick: find the evidence, then answer from it.

Takeaways

  
What to remember

  

    
🧩 Components, not magic
Role, Task, Context, Examples, Format, Constraints, Tone. Each removes a guess.

    
⚙️ System vs user
Standing instructions go in the system prompt or instruction file; the specific ask goes in the message.

    
🧱 Structure with tags
Wrap instructions, documents, examples and format in XML tags. Refer to them by name; ask for the answer in tags.

    
✅ Best practices
Be clear, explain why, show examples, say what you want back, documents first and question last. Then test.
