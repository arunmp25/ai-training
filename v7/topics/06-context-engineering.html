The bigger picture

Your prompt is one slice of the context

In a real AI app or agent, the context is assembled from many sources for every single request. Someone (or something) has to decide what goes in.

Context engineering = designing the system that decides, for every request, which information goes on the desk, in what form, and what is left off.
Good context is:
  • Relevant: only what this task needs
  • Fresh: up to date, not last year’s policy
  • Consistent: no contradicting instructions
  • Compact: summarised where possible
  • Structured: clearly labelled sections

Deep dive · Prompt caching

Put what doesn’t change first

Providers can cache the start of a prompt. If the start is identical, the next request reuses it: cheaper and faster. Switch between the two orders.

Cached reads cost about a tenth of normal input. The cache lasts about 5 minutes by default, longer as an option. Check your provider.
⏱ 3 min

🎤 Say Caching works on the beginning of the prompt: if the first part is byte-for-byte the same as last time, the provider reuses it. So put the stable parts first, such as the system prompt, tool definitions and long reference documents, and the changing question last.

  • The wrong order puts something that changes, such as today’s date or the user’s question, at the top. Then nothing after it can be cached.
