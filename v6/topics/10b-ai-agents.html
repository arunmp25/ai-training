AI agents: from prompt to agent

A prompt gets one answer. An agent gets a goal, chooses its own steps and uses tools until the job is done. Here is how that differs from prompting, and how teams build agents with LangChain and LangGraph.

⏱ 30 sec

🎤 Say This is the first of two optional topics that close Session 3, for teams that build agents. In Topic 15 we saw the agent loop, and in Topics 16 to 18 the harness and safety around it. Now we put it side by side with plain prompting, take an agent apart, and build one in code with two popular frameworks.

  • Audience check: who has used ChatGPT or Claude (prompting) and who has used Claude Code or Copilot agent mode (an agent)?

🎤 Say Same question, three designs. A single prompt can only guess. A fixed chain gets the facts but runs the same steps every time. An agent decides its own steps, and even checks the guidelines without being told.

Side by side

Prompting vs an agent

Neither is better. They suit different jobs.

💬 Prompting🤖 Agent
You give itA question or instructionA goal, tools and rules
Who decides the stepsYou, one prompt at a timeThe model, in a loop
Model callsOne per answerMany: one per step, until done
Can it act?No. It writes text you then useYes. It calls tools: search, quote, update, send
StateThe chat historyHistory plus everything it has found and done
Cost and speedLow and fastHigher and slower: every step is a model call
PredictabilityHighLower: different inputs take different paths
New risksWrong or made-up answersWrong actions, loops, runaway cost, prompt injection
Rule of thumb: if you can write the steps down in advance, use a prompt or a workflow. Use an agent when the steps depend on what it finds.
⏱ 2 min

🎤 Say Prompting is one request, one answer, with you in charge of every step. An agent takes a goal and decides its own steps, which makes it more capable, slower, more expensive and harder to predict.

  • The last row matters most: an agent can take wrong actions, not just say wrong things. That is why Topics 16 to 18 exist.
  • The rule of thumb is from Anthropic’s guidance on building agents: start with the simplest thing that works.
Anatomy

Six parts of every agent

Whatever the framework, an agent is built from the same parts. Click each one.

⏱ 3 min

🎤 Say Every agent, whatever the framework, has the same six parts: a model, instructions, tools, memory, a loop with a stop condition, and guardrails. Frameworks differ in how much of this they build for you.

  • The stop condition is the part people forget. Without it an agent can loop and spend money for ever.
  • Guardrails link forward to Topic 18 (safety) and Topic 17 (hooks and permissions in a harness).

🎤 Say Here is a complete agent in LangChain. The tools are ordinary functions with a docstring. create_agent joins the model, the tools and the instructions, and one invoke call runs the whole loop.

  • Step 2: the docstring is the tool description. A vague docstring means a confused agent (Topic 12).

Animated · LangGraph

LangGraph: the same agent, drawn as a graph

Nodes do work, edges decide what runs next, and the state travels between them. Press → or Play.

⏱ 3 min

🎤 Say LangGraph shows the loop as a graph. The agent node calls the model. A conditional edge checks for tool calls: if there are any, go to the tools node and back; if not, finish. The state, the list of messages, travels around the graph and is saved after every step.

  • The loop is the same as before. What changes is that you can see it and edit it.
  • Saved state is the quiet superpower: it is what lets an agent pause for a human and resume (Topic 20).

Choosing

LangChain, LangGraph, or neither?

LangChain’s create_agent is itself built on LangGraph. The question is how much of the flow you want to control.

🐍 Plain code

The 30-line loop from Topic 13, using the provider’s SDK.

Use when you have one model, a few tools and want no dependencies.

🦜 LangChain

create_agent: a standard tool loop with memory and middleware.

Use when the standard loop fits and you want to switch models or add tracing easily.

🕸️ LangGraph

Your own graph of nodes, edges and saved state.

Use when you need branches, parallel steps, quality loops, human approval, or long runs that resume.

Every pattern in the next topic can be built in plain code, but LangGraph makes them explicit. You will see the LangGraph version of three of them.
⏱ 2 min

🎤 Say Three options. Plain code for simple, dependency-free agents. LangChain when the standard loop fits. LangGraph when you need to design the flow yourself.

  • Ask the room which they would pick for a claims-triage bot (probably LangGraph, because of human approval).
  • Bridge: the next topic is about those flows, the design patterns.

Takeaways

What to remember

🎯 Goal, not script

Prompting answers once. An agent chooses its own steps, using tools in a loop, until the goal is met.

🧩 Six parts

Model, instructions, tools, memory, a loop with a stop condition, and guardrails.

🦜 Frameworks help

LangChain gives you the loop; LangGraph lets you draw your own flow with saved state.
