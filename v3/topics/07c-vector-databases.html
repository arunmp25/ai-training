⏱ 2 min
🎤 Say Comparing the question with every chunk is perfectly accurate and fine for small collections. At millions of chunks it becomes too slow.
  • At a few thousand chunks, brute force is fine (and simplest). At millions, every question would scan everything: seconds per query.
  • Also note memory: a vector of 1,536 numbers is ~6 KB, so 100 million chunks is ~600 GB before any index.
  • The answer is Approximate Nearest Neighbour (ANN) search: next slide.






  
How it gets fast

  
ANN search: hop through a graph instead of checking everyone

  
HNSW, the most common index, links each vector to its near neighbours, plus a sparse “express” layer of long links. Search starts at the top, hops greedily towards the question, then drops down for the fine search. Click New question.

  

    
    

      

      

      
Approximate means it can occasionally miss the true nearest neighbour, in return for being thousands of times faster. Settings let you trade speed for accuracy.

    

  

  
⏱ 4 min
🎤 Say HNSW is like finding a house in a new city: take the motorway to the right district, then walk the local streets. Fast, and almost always finds the nearest results.
  • Analogy: finding a house in a new city. Take the motorway (express layer) to the right district, then walk the local streets (bottom layer).
  • Other index types: IVF groups vectors into clusters and only searches the closest few clusters; PQ (product quantisation) compresses vectors to save memory. Most products pick sensible defaults for you.
  • Point at the stats: it checked a handful of points, not all of them.

Better retrieval

  
Hybrid search: keywords and meaning, combined

  
Ever searched for policy POL-88812 and got POL-88821? Meaning search finds “similar”, and similar numbers aren’t the same policy. Keyword search (BM25) is great at exact codes and names. Vector search is great at meaning. Hybrid runs both and merges the rankings. Pick a question. ✅ = the chunk that actually answers it.

  

  

  
Merged with Reciprocal Rank Fusion: each chunk scores 1 ÷ (60 + its rank) in each list, and the scores are added. Being near the top of either list helps.

  
⏱ 3 min
🎤 Say Search for POL-88812 and meaning search may return POL-88821, because similar numbers look alike to an embedding. Keyword search catches exact matches, so we run both.
  • Error code question: vector search puts E-4417 first (it looks alike to an embedding); keyword nails E-4471.
  • “Won’t let me in”: keyword search gets distracted by “laptop” (bag policy, refresh) and buries the answer at #3; vector search nails it.
  • Uber question: keyword grabs the Uber Business setup page; vector understands “ride-hailing”. Hybrid lifts the chunk that ranks well in both.
  • Hybrid gets both right. That’s why most production RAG uses hybrid search.






  
Better retrieval

  
Re-ranking: a careful second read of the shortlist

  
Vector search compares two summaries (vectors), so it’s fast but rough. A re-ranker reads the question and each chunk together, so it’s slower but much sharper. Use it on the top 20–50 only. Question: “Can I bring my dog to the office?”

  

    

    

      

      

    

  

  
⏱ 2 min
🎤 Say A re-ranker reads the question and each candidate together. It is slower but much more precise, so it only sees the shortlist.
  • The classic two-stage design: retrieve broadly and cheaply (top 50), then re-rank precisely and keep the top 3–5 for the prompt.
  • Technical names: vector search uses a bi-encoder (each text embedded separately); a re-ranker is a cross-encoder (both texts read together).

Evaluation

  
Measure retrieval with a golden question set

  
Write 50–200 real questions and note which chunk answers each. Then measure where that chunk ends up. Move k.

  

    

    

      
k (chunks kept): 

      

      
Also check the answers: are they grounded (every claim supported by a retrieved chunk) and correct? More in Topic 17.

    

  

  
⏱ 2 min
🎤 Say Measure retrieval with a set of real questions. If the right chunk is not retrieved, the model cannot use it.
  • Recall@k: how often the right chunk is in the top k. If it’s not retrieved, the model can’t use it.
  • MRR (mean reciprocal rank): rewards putting the right chunk near the top.
  • Re-run the set every time you change chunking, embeddings, k or the re-ranker.
