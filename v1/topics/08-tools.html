Topic 08

Tools: giving AI hands

A model can only produce text. Tools let that text turn into actions: looking things up, calculating, updating systems.

⏱ 30 sec
  • Also called function calling or tool use. Same thing.
The key insight

The model doesn’t run tools. It asks for them.

Like a surgeon saying “scalpel”: the model writes a structured request, your software carries it out, and the result goes back to the model.

⏱ 2 min
  • Crucial for safety: your software decides whether to actually run the request. That’s where permissions and approvals live (Topic 13).

Tool design

The model only knows a tool by its description

Request: “Find Dana Lee’s email address.” Compare vague and clear tool descriptions.

⏱ 2 min
  • Tool descriptions are prompts too. Everything from Topic 05 applies: be specific, say when to use it and when not to.

Risk

Not all tools are equally risky

Classify each tool by what could go wrong. This decides how much approval it needs.

⏱ 2 min
  • Simple policy many teams use: read-only tools run freely, reversible writes are logged, and irreversible actions need a human to click Approve.

Takeaways

What to remember

🙋 It asks, you act

The model writes a structured tool request; your software runs it and returns the result.

📝 Descriptions are prompts

Clear names and descriptions mean the right tool gets picked.

⚠️ Mind the risk

Read-only runs freely; irreversible actions need approval.
